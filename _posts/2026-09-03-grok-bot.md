2026년 8월 들어 Grok Bot(그록봇) 이야기가 갑자기 많아졌습니다. Grok 채팅의 별칭이 아니라, **일을 배정하면 앱에 직접 들어가 끝까지 처리하는 AI 팀원** 제품입니다. 이 글은 공식 발표와 문서, 확인된 웹 보도를 기준으로 2026-09-03 시점에 정리했습니다. X(Twitter) 타임라인의 개별 트윗은 API로 안정적으로 수집하지 못했고, X와 맞닿는 공식 경로는 **X Premium+ 구독을 Grok Bot 사용량으로 연결**할 수 있다는 점입니다.

## 한 줄 요약

- **출시:** 2026-08-11 얼리 베타. SpaceXAI(구 xAI) + Cursor 계정으로 로그인하는 데스크톱/iOS 앱.
- **핵심:** 봇마다 "역할"은 나눠도, **계정당 클라우드 컴퓨터는 한 대**입니다. 브라우저·파일·로그인을 공유하고 노트북을 꺼도 일이 이어집니다.
- **접근:** 유료 Cursor 플랜(Pro / Pro+ / Ultra, Teams)에 포함. SuperGrok / SuperGrok Plus / Heavy, 또는 **X Premium+** 를 연결해도 사용량을 받을 수 있습니다. Enterprise는 계정팀/웨이트리스트.
- **주의:** 봇을 여러 개 만든다고 권한이 나뉘지 않습니다. Cursor **Privacy Mode (Legacy)** 는 Grok Bot을 막습니다.

## 챗봇 / 코딩 에이전트와 뭐가 다른가

공식 포지션은 "프롬프트하는 에이전트"가 아니라 **동료에게 일을 맡기는 느낌**입니다.

1. **클라우드 컴퓨터.** 브라우저, 파일시스템, 터미널이 있는 상시 VM. MCP/커넥터가 없는 사이트도 화면을 조작합니다. ([computer and apps](https://docs.x.ai/grok-bot/computer-and-apps))
2. **끝나면 오거나, 승인만 물을 때 옵니다.** 중간 초안을 사람이 복사해 옮기는 구조가 아니라, CRM·메일·이슈 트래커 같은 **실제 도구에 결과물이 남는다**는 주장입니다.
3. **여러 봇이 병렬.** 봇끼리 메시지·그룹챗으로 일을 넘깁니다. 다만 화면은 봇마다 있어도, **보안 경계는 봇이 아니라 사용자 계정**입니다.
4. **한 번 보여 주면 루틴.** 사람이 하는 경로를 따라가게 한 뒤, 스케줄/요청으로 다시 돌립니다.
5. **사용량은 Grok/Cursor 본편과 별도 미터.** 봇에게 맡긴 작업이 기존 Grok·Cursor 쿼터를 깎지 않는다고 공식 발표에 적혀 있습니다.

Cursor 포럼 공지([Introducing Grok Bot](https://forum.cursor.com/t/introducing-grok-bot/168053))도 같은 세 축입니다. 컴퓨터, 봇 간 협업, 시범 → 루틴.

## 웹에서 반복되는 이야기

확인된 웹 보도·해설에서 공통으로 나오는 포인트만 골랐습니다.

- **카테고리 경쟁.** The Verge는 ChatGPT Work, Claude Cowork, Copilot Tasks 같은 "일을 맡기는 AI" 대열에 올려 설명합니다. Grok 채팅의 연장선이라기보다 **에이전트 제품**으로 읽힙니다.
- **내부에서 먼저 썼다.** 세일즈 아웃바운드, 마케팅, 사무실 운영, 버그 재현/티켓처럼 SpaceXAI 안에서 프로토타입이 돌았다는 것이 론칭 글의 핵심 서사입니다.
- **커뮤니티.** Cursor 포럼에는 출시 이후 Grok Bot으로 돌리는 실험(예: 에이전트만 글 쓰는 피드, 봇 팩 디렉터리)이 올라오기 시작했습니다. 제품이 채팅 데모를 넘어 **실제 워크로드**로 쓰이는지 보는 창입니다.
- **가격 논쟁.** 초기는 Heavy/Ultra 중심이라 "비싸다"가 메인 반응이었고, 8월 말 플랜 확대 이후에는 **주간 사용량·온디맨드**가 다음 쟁점입니다. 무료 체험은 날짜가 아니라 **사용량 크레딧**(에이전트 스텝/토큰)이며, 큰 작업 한 번에 거의 다 쓸 수 있습니다.

X 타임라인은 이 환경에서 원문을 안정적으로 긁지 못했습니다. 대신 공식 문서가 X와 직접 연결하는 지점은 분명합니다. **X Premium+를 Grok Bot 플랜 화면에서 연결하면**, Cursor 계정에 Grok Bot 사용량이 부여됩니다. SuperGrok Lite, SuperGrok Team/Enterprise 연결은 지원하지 않습니다.

## 요금과 접근 (문서 기준)

[Plans and billing](https://cursor.com/help/grok-bot/plans) 요약입니다. 금액은 플랜 페이지가 자주 바뀌므로 여기 숫자로 고정하지 않습니다.

- **Cursor Ultra / Pro+ / Pro:** 같은 Cursor 계정으로 Grok Bot 로그인. 주간 허용량은 Ultra > Pro+ > Pro.
- **Cursor Teams (셀프서브):** 멤버 전원 접근. Premium 시트를 따로 달라고 할 필요 없음. 사용량은 시트 허용량(+ 기본 온디맨드).
- **Cursor Enterprise:** 어드민/어카운트 팀이 켜 줘야 함.
- **SuperGrok / Plus / Heavy, X Premium+:** Grok Bot 화면에서 **링크**. Cursor 플랜을 바꾸거나 취소하지 않고 사용량만 부여. 한 번 연결하면 다른 Cursor 계정으로 옮길 수 없음.
- **별도 Grok Bot 구독은 없음.**
- macOS와 iOS는 **같은 주간 버킷**.

## 보안: 봇을 나눠도 컴퓨터는 하나

공식 문서 [Approvals, security, and privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy)가 가장 중요합니다.

- 모든 봇이 **계정에 할당된 클라우드 컴퓨터 한 대**를 씁니다. 파일, 브라우저 세션, CLI 자격 증명이 공유됩니다.
- 봇 화면이 여러 개여도 **보안 경계가 아닙니다.** "리서치 봇"과 "배포 봇"을 나눠도 로그인은 같이 보입니다.
- 비밀번호·2FA·결제는 봇이 타이핑하지 않고, 컴퓨터를 사람에게 넘기거나 마스킹된 시크릿 입력을 씁니다.
- **Privacy Mode (Legacy) 는 Grok Bot을 차단**합니다. 클라우드 저장이 필요하기 때문입니다. 팀의 일반 Privacy Mode는 Cursor 설정을 따릅니다.
- 봇을 지워도 공유 컴퓨터의 파일·세션이 자동으로 사라지지 않습니다. 로그아웃, 커넥터 해제, 민감 파일 삭제가 따로 필요합니다.

The Verge도 같은 조건을 첫 문단 근처에서 짚습니다. 도구에 **실제 로그인**을 맡길 수 있어야 이 제품이 성립합니다.

## 지금 시점에서 보면

Grok Bot은 "더 똑똑한 Grok 채팅"이 아니라 **컴퓨터 사용 에이전트를 메신저 UX로 포장한 팀 제품**입니다. 8월 11일 좁은 베타로 시작해 2주 만에 유료 Cursor·SuperGrok 쪽으로 문을 연 상태고, 엔터프라이즈는 아직 별도 롤아웃입니다.

블로그 독자 입장에서 바로 쓸 체크리스트는 이 정도입니다.

1. Cursor 유료 플랜(또는 SuperGrok / X Premium+ 연결)이 있는지 확인한다.
2. Legacy Privacy Mode면 켜지기 전에 막힌다.
3. 봇을 역할별로 나눠도 **로그인은 공유**된다고 가정하고, 최소 권한 계정 + 승인 게이트부터 건다.
4. 체험 크레딧은 긴 작업 한 번에 소진될 수 있다. 작은 일부터.
